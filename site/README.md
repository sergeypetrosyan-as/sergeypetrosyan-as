# NEON ARCADE — gaming hub

The game launcher published by GitHub Pages for this repository, drawn in the **19_mystical-western** design system (a frontier observatory: engraved desert skyline, carved moon, tarot-card games) in the Actual Solutions brand colours:

**https://sergeypetrosyan-as.github.io/sergeypetrosyan-as/**

The hub links to every playable game in the repo, with a featured spotlight, an about section and full SEO/social metadata. The profile `README.md` at the repo root is a separate thing: GitHub shows it on the profile page, while Pages serves the hub's `index.html`.

## How it works

- **Vanilla TypeScript and Vite.** No framework, because the page is static content plus a little behaviour.
- **One game registry.** `src/data/games.ts` drives the cards, the spotlight, JSON-LD structured data and `sitemap.xml`.
- **Pre-rendered at build time.** Components in `src/components/` are pure functions that return HTML strings. A Vite plugin renders them into `index.html`, so the whole page works without JavaScript. Client JS (`src/lib/`) only adds the mobile menu, active-section state and the hover/focus switch from a card's still to its animated loop.
- **Validated links.** The build fails if a playable game's `playUrl` has no `index.html` in the repo, or if any artwork file is missing.
- **Design tokens.** Colour comes from `design/19_mystical-western/` (palette.mjs → generated tokens.css), imported by `src/styles/tokens.css`, which maps it to roles and adds radii, spacing, type, motion and layers. Rye is for short titles only; Zilla Slab for labels and buttons; Public Sans for reading text.
- **Motion budget.** One decorative motion: three stars in the hero drift off the telescope's sight line and back (CSS, 9 s, seamless). The hero copy enters once on load; cards lift 2px on hover. Nothing reveals on scroll. Animations pause while the tab is hidden, and `prefers-reduced-motion` stops them and keeps card stills instead of loops.

```
site/
├── index.html            # head/SEO shell; <!--app--> is replaced at build time
├── vite.config.ts        # prerender, registry validation, dev server for the real games

```

## Adding a game

1. Put the built game in its own folder at the repo root, e.g. `my-game/index.html`.
2. Add a scene for it to `tools/profile-art/src/cards.mjs` (one seamless motion, an arcana and a numeral) and run `npm run build` there. That writes its tarot card loop to `assets/cards/<id>.gif` and its still to `public/arcade/media/<id>-card.webp`.
3. Add an entry to `src/data/games.ts` with `status: 'playable'` and `playUrl: './my-game/'`. For a game that isn't ready, use `status: 'coming-soon'` and leave out `playUrl`; it renders as a disabled card.
4. Run `npm run build` and commit.

## Develop and build

```bash
cd site
npm install
npm run dev        # http://localhost:5210 — also serves /games/ and /assets/ from the repo
npm run build      # type-check + validate registry + write the hub into the repo root
```

The build writes `index.html`, `sitemap.xml`, `favicon.svg`, `og-image.jpg`, `apple-touch-icon.png`, `robots.txt`, `404.html` and `arcade/` into the repository root. Nothing else there is touched.

## Deployment

GitHub Pages already publishes this repository from **`main` / root**, so committing the build output is the deployment. No settings change is needed. `.github/workflows/arcade-hub-build.yml` type-checks and builds on every change and warns if the committed output is stale. It never deploys.

### Why `https://sergeypetrosyan-as.github.io/` (the bare domain) is a 404

GitHub serves the bare user domain **only** from a repository named exactly `sergeypetrosyan-as.github.io`, and this account doesn't have one. The profile repository `sergeypetrosyan-as` is a *project* site, so it lives under `/sergeypetrosyan-as/`. The hub is deployed there.

To serve the hub at `/` and every game at `/games/<game>/`, use the mirror kept in [`user-site/`](./user-site). Its workflow copies this repo's built output (no secrets needed, since this repo is public) and deploys it, on push, on demand, and every 30 minutes:

1. On GitHub, create a new **public** repository named exactly **`sergeypetrosyan-as.github.io`**. Leave it empty: no README, license or .gitignore.
2. In that repo, open *Settings → Pages* and set *Build and deployment → Source* to **GitHub Actions**.
3. Push the mirror:
   ```bash
   cd site/user-site
   git init -b main && git add . && git commit -m "Mirror NEON ARCADE at the root domain"
   git remote add origin https://github.com/sergeypetrosyan-as/sergeypetrosyan-as.github.io.git
   git push -u origin main
   ```
4. After the first workflow run, `https://sergeypetrosyan-as.github.io/` serves the hub and `https://sergeypetrosyan-as.github.io/games/unfall/` (and the others) serve the games.

All site paths are relative, so the same files work under both `/` and `/sergeypetrosyan-as/`.
